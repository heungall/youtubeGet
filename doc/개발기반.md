# 개발 기반 및 결정 기록

검토일: 2026-11-11. 관련 작업: T-002, T-003, T-018, T-020, T-024, T-028.

## 이번 구현 범위

Next.js App Router / TypeScript / Tailwind CSS와 shadcn/ui 방식의 공통 UI를 구성했다. 이메일·비밀번호 로그인/로그아웃, 세션 갱신, 사용자별 현황·영상 조회, 제목 검색·자막 필터·50개 단위 페이지네이션을 구현했다. YouTube 검색·수집, 데이터 쓰기, 자막 입력, 분석, 월별 선정은 후속 작업이다. 실제 DB 조회 실패를 빈 목록이나 0개 성공으로 표시하지 않는다.

사용자의 요청은 현재 저장소에서 개발을 시작하는 범위로 해석한다. Sites 지침의 로컬 작업 경로를 적용하며, 외부 Site 등록·배포는 수행하지 않는다. 배포 대상은 요구사항에 기재된 Vercel이다.

## 사용자와 데이터 소유권

- 조직·역할·멀티테넌트 기능은 추가하지 않는다. Supabase Auth의 사용자 ID를 기본 소유자로 사용한다. 초기 로그인은 Supabase 관리 화면에 생성한 내부 이메일·비밀번호 계정으로 제한하고 공개 회원가입 UI는 제공하지 않는다. 실제 가입 비활성화는 프로젝트 Auth 설정에서도 필요하다. 메일 초대/재설정 흐름은 후속 범위다.
- 인증 전에는 소유 데이터를 읽거나 쓸 수 없다. 모든 사용자 테이블에 RLS를 적용하고 `auth.uid() = owner_id`로 제한한다. 고정 카테고리는 인증 사용자에게 읽기만 허용한다.
- 영상·채널의 YouTube ID 중복은 **사용자 소유 범위 내**에서 방지한다. `unique(owner_id, youtube_video_id)`와 `unique(owner_id, youtube_channel_id)`를 사용한다. 요구사항 초안의 전역 unique와 다른 점은 서로 다른 사용자의 수집이 서로의 개인 데이터 존재를 노출하거나 충돌하지 않게 하기 위함이다.
- 자식 테이블은 `(부모 id, owner_id)` 복합 외래키를 사용한다. RLS만으로 자식의 소유자를 검사하면 타인 영상 ID를 연결할 수 있으므로 DB 제약도 적용한다.
- service-role 클라이언트는 만들지 않으며 secret/service-role 키 설정은 거부한다. 서버 클라이언트를 로그인·조회 화면에 연결하고 `proxy.ts`에서 `getClaims()`로 세션을 검증·갱신한다. 쿠키와 캐시 헤더를 리다이렉트 응답에도 보존한다. 서버 조회는 Proxy와 별도로 인증을 확인하고 사용자 ID 조건과 RLS를 함께 적용한다. 전체 DB 생성 타입은 실제 프로젝트에서 생성해야 하며 현재 타입은 조회 DTO다.
- 사용자 화면은 동적으로 렌더링하고 캐시를 공유하지 않는다. `/login`과 `/settings`는 로그인 전에도 접근 가능하다. 설정 페이지는 키 값이나 타인 데이터를 노출하지 않는다. 인증 서버 장애는 데이터 접근 허용으로 처리하지 않는다.
- 현재 인증은 서버에서만 처리하므로 세션 쿠키에 HttpOnly/SameSite=Lax를 사용하고 프로덕션에서는 Secure를 적용한다. 추후 브라우저 Supabase 클라이언트를 도입할 경우 이 쿠키 설계와 호환성을 먼저 검토한다.
- 로그인 복귀 주소는 앱 내부의 허용된 경로로 제한한다. DB/Auth 네트워크 호출은 10초 제한과 `no-store`를 적용한다. 라이브러리 제목 검색은 와일드카드를 이스케이프한 단일 `ilike` 조건으로 전달한다.

## 상태·추천·정합성

- 자막 표시와 원문 확보를 서로 다른 필드로 저장한다. 자막 표시 있음만으로 원문이 있다고 판단하지 않는다.
- 분석은 버전별로 저장하며 `summary_source`는 필수다. 메타데이터 기반 결과는 신뢰 수준 `low`로 제한한다. 자막 기반 분석은 같은 영상·소유자의 자막 레코드를 반드시 참조한다.
- 키워드 `origin`과 `confirmed_at`을 별도로 저장한다. 자동 제안(미확정)과 사용자 확정을 구별한다. 편집 UI와 전체 편집 감사 이력(T-014)은 후속 구현이다.
- 디테일 키워드는 DB 트리거에서 공백·대소문자를 정규화한다. 한글의 의미 유사도나 형태소 분석은 포함하지 않는다.
- 월별 캠페인은 사용자·월당 한 개, 캠페인 내 영상은 한 번만 연결한다. 추천 점수는 음수가 아닌 정렬용 추정치이며 정확도 백분율이 아니다.
- 동기화 작업에 페이지 커서, 처리량, 시도 횟수, 추정 쿼터 사용량을 기록할 필드를 준비한다. 실제 API 호출과 자동 재시도는 미구현이다.

## 보관·갱신 및 운영 전 확인

[YouTube 개발자 정책](https://developers.google.com/youtube/terms/developer-policies)의 API 데이터 보관 규칙에 따라 공개 메타데이터는 통상 30일 이내 갱신 또는 삭제 경로가 필요하다. 채널·영상에 `last_fetched_at` 및 `refresh_due_at`을 둔다. 입력 자막에는 기본 30일의 `retention_until`을 두어 보관 결정을 명시한다. 이 필드는 **자동 삭제를 실행하지 않는다**. 갱신·삭제 작업, 삭제/비공개 영상 처리, 관련 분석 데이터의 처리 정책을 T-023에서 구현·검증하기 전 운영 수집을 시작하지 않는다. 사용자 작성 분류와 API 기반 데이터의 구분도 해당 작업에서 다룬다.

[Vercel Hobby 정책](https://vercel.com/docs/plans/hobby)은 개인·비상업 사용으로 제한한다. 마케팅 업무용 운영에 Hobby 사용 가능하다고 가정하지 않으며, 배포 전 적합한 플랜·비용을 확인한다. 유료 플랜을 자동 가입하지 않는다.

[Supabase 요금제](https://supabase.com/pricing)와 [공식 Free 안내](https://supabase.com/kb/faqs/platform/free-postgres-for-side-projects)에 Free DB 500MB와 저활동 프로젝트 일시 중지 조건이 기재되어 있다. 실제 가입 시 상업 이용 조건, 저장 공간, 백업·보관 요구를 다시 확인한다. 현재 외부 프로젝트 생성·요금제 가입·사용량 발생 작업은 수행하지 않았다.

YouTube 쿼터, 검색 비용, 제3자 자막 권한, AI 플랜은 해당 연동을 구현하는 시점에 공식 문서로 재확인한다. 이번 단계에서 자막 다운로드나 외부 AI 호출은 제공하지 않는다.

## 의존성 선택

루트 `package-lock.json`으로 해석 버전을 고정한다. 상용 서비스 가입을 요구하는 패키지는 추가하지 않았다.

개발 의존성의 minimatch 취약점([GHSA-g3hv-75wg-m249](https://github.com/advisories/GHSA-g3hv-75wg-m249))을 해결하기 위해 `@typescript-eslint/typescript-estree` 아래 minimatch만 11.0.1 이상으로 override했다. 린트·타입 검사·테스트·빌드로 호환성을 확인한다. ESLint 10은 현재 설치되는 Next의 React/import/a11y 플러그인 peer 범위와 충돌해 사용하지 않고 9.39.5로 고정한다. 이 버전의 지원 종료 경고는 남아 있으므로 플러그인 호환 업데이트 후 ESLint 10으로 전환하는 작업을 추적한다.

| 패키지/그룹 | 이유 | 라이선스 및 운영비 영향 |
|---|---|---|
| Next.js, React, React DOM | 요구사항의 앱/서버 프레임워크 | MIT, 패키지 자체 과금 없음 |
| Tailwind CSS, PostCSS 플러그인 | 공통 UI 스타일과 빌드 | MIT, 패키지 자체 과금 없음 |
| Radix Slot, CVA, clsx, tailwind-merge | shadcn/ui의 조합 가능한 버튼/스타일 | MIT / CVA는 Apache-2.0, 패키지 자체 과금 없음 |
| lucide-react | 메뉴·상태 아이콘 | ISC, 패키지 자체 과금 없음 |
| Supabase JS/SSR, server-only | 사용자 세션 기반 서버 DB 클라이언트 및 서버 경계 | MIT, 외부 Supabase 사용 시 플랜 한도 적용 |
| TypeScript, 타입 선언, ESLint/Next 설정 | 정적 검사 | Apache-2.0 / MIT 계열, 개발 도구 |
| Vitest | 테스트 실행 | MIT, 개발 도구 |
| PGlite | 별도 Docker 없이 실제 PostgreSQL 마이그레이션/RLS 테스트 | Apache-2.0, 포함 PostgreSQL은 PostgreSQL License, 개발 도구 |

## 검증 경계

PGlite 테스트는 Supabase의 `auth.users`, `auth.uid()`, `anon`, `authenticated`를 최소 구성으로 대체한다. 프로젝트 SQL과 PostgreSQL의 RLS·제약·트리거를 실제 실행하지만 Supabase의 JWT 검증, Auth 서버, PostgREST, 원격 운영 설정까지 검증하지 않는다. 외부 Supabase 적용 및 두 실제 계정의 접근 차단, YouTube 연결 검증은 환경 준비 후 별도 수행한다.

로그인 액션·세션 갱신 테스트는 Auth 응답을, 조회 테스트는 실제 Supabase SDK의 HTTP 응답을 모의한다. 외부 프로젝트의 연결 성공을 증명하지 않는다. 사용자가 Vercel 첫 배포와 Supabase 초기 SQL 적용을 완료했다고 확인했으며, 로컬에는 실제 환경변수/계정이 없어 원격 검증은 수행하지 않았다. SSR 구현 근거는 [Supabase 공식 문서](https://supabase.com/docs/guides/auth/server-side/creating-a-client)다.
