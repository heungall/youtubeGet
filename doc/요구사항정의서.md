# 유튜브 콘텐츠 키워드 아카이브 — 요구사항정의서

- 문서 버전: v0.4
- 작성일: 2026-11-11
- 상태: Google 로그인·DB 조회 코드 구현 (실제 OAuth 계정 검증 및 영상 수집 연동 전)
- 프로젝트 가칭: YouTube Keyword Archive

## 1. 목적 및 배경

마케팅 외주업체가 전달한 **월별 키워드**에 가장 적합한 유튜브 영상을 빠르게 찾아 선정·관리한다. 특정 브랜드 유튜브 계정의 로그인 권한 없이도 **공개 영상**을 검색하고 수집한 후, 영상별 **대표 키워드 / 디테일 키워드 / 서머리**를 축적하여 재검색 가능한 콘텐츠 사전을 만든다.

## 2. 목표와 범위

### 2.1 목표

1. 공개 유튜브 영상 및 특정 공개 채널의 업로드 영상을 **페이지 단위로 나누어 수집**한다.
2. 영상의 제목·설명·공개 메타데이터와 자막 제공 여부를 확인한다.
3. 필요 영상을 사용자가 선택하여 분석 요청한다. **자막 원문 확보는 권한·접근 가능성에 따라 달라짐**을 UI에 명확히 표시한다.
4. 영상마다 대표 키워드(복수), 디테일 키워드(복수), 서머리 및 분석 근거를 저장한다.
5. 월별 요청 키워드에 대한 매칭 후보, 추천 근거, 최종 선정 결과를 관리한다.
6. 중복 수집과 중복 분석을 최소화하여 무료 사용량 및 운영 비용을 통제한다.

### 2.2 MVP 범위

- YouTube Data API v3 기반 검색 및 채널 업로드 재생목록 수집
- 1회 최대 50개씩 페이지네이션, 이어받기 및 중복 제거
- Supabase에 영상/키워드/서머리/월별 선정 결과 영구 저장
- 영상 상세 페이지와 메타데이터 기반 1차 키워드 추천
- `contentDetails.caption` 등을 활용한 자막 표시 여부 확인(원문 획득 보장 아님)
- 직접 입력/붙여넣기한 자막을 대상으로 상세 키워드와 서머리 생성 또는 수정
- 검색, 필터, 관련도 정렬, 선정 상태 관리, CSV 내보내기
- 기본 사용 로그와 에러/제한 안내

### 2.3 MVP 제외 및 후속 검토

- 유튜브의 **모든 영상** 일괄 확보
- 브랜드 계정 권한 없이 타인의 자막을 공식 API로 일괄 다운로드
- 접근 권한이 없는 자막에 대한 우회·비공식 스크래핑의 기본 제공
- 모든 영상에 대한 일괄 AI 전문 분석 및 무제한 무료 AI 처리 보장
- 동영상 파일 다운로드, 재배포 또는 비공개 영상 접근
- 멀티테넌트·복잡한 조직 권한·유료 과금 시스템

## 3. 사용자와 핵심 시나리오

**주 사용자:** 내부 콘텐츠·마케팅 담당자.

1. 운영자가 브랜드 채널 URL/ID를 등록하고 공개 영상들을 순차적으로 불러온다.
2. 영상 목록에서 `자막 표시 있음 / 없음 / 확인 안 됨` 상태를 본다.
3. 외주업체가 준 월별 키워드(예: `기도`)를 입력하여 후보 영상들을 탐색한다.
4. 후보 영상을 열어 메타데이터를 확인하고, 이용 가능한 자막 텍스트를 붙여넣거나 허용된 방식으로 제공받아 분석한다.
5. 대표 키워드와 디테일 키워드, 요약을 검토·수정한 후 저장한다.
6. 매칭 후보를 해당 월의 선정 목록에 넣고 CSV로 내보낸다.
7. 다른 달에도 이미 분석된 영상을 재사용한다.

## 6. 자막 처리 정책

- **자막 표시 여부 ≠ 자막 다운로드 권한 ≠ 원문 추출 성공**. 별도 필드와 상태로 저장한다.
- YouTube Data API의 공개 영상 `contentDetails.caption` 값은 자막 유무의 참고 신호이며, 표시 정보가 불완전할 수 있다.
- 제3자 채널의 자막 원문은 공식 API만으로 임의 다운로드할 수 있다고 가정하지 않는다.
- 분석 입력 우선순위: (1) 권한 있게 제공받은 자막, (2) 사용자가 입력한 자막, (3) 제목·설명·태그만으로 생성한 메타데이터 요약.
- 자막이 없는 경우에도 메타데이터 기반 키워드 제안을 제공할 수 있으나, **영상 내용을 실제 확인한 요약인 것처럼 표시하지 않는다**.
- 자막 자동 확보 방법은 별도 PoC를 통해 법적·약관상 허용 여부와 기술적 성공률을 확인한 뒤 채택한다.

### 6.1 상태 모델

- `caption_indicator`: `available` / `unavailable` / `unknown`
- `transcript_status`: `not_requested` / `available` / `unavailable` / `failed` / `manual`
- `analysis_status`: `not_started` / `metadata_only` / `pending` / `transcript_analyzed` / `failed`
- `summary_source`: `metadata` / `transcript` / `manual`

실제 스키마 구현 시 사용자 소유/접근 범위와 RLS 정책을 확정한다.

### 8.1 초기 스키마 결정 (2026-11-11)

- 사용자 데이터는 Supabase Auth의 `owner_id`로 분리하고 모든 사용자 테이블에 RLS를 적용한다. 조직·역할 권한은 MVP에 추가하지 않는다. 로그인 방식은 T-018에서 확정한다.
- 채널과 영상은 사용자 소유 범위에서 YouTube ID를 유일하게 관리한다(`unique(owner_id, youtube_video_id)` 등). 동일 사용자의 재수집 중복을 방지하며 타인 데이터와 충돌하지 않도록 한다.
- 연결 테이블은 소유자를 포함한 복합 외래키로 타인 데이터 참조를 차단한다. 고정 13개 카테고리는 로그인 사용자에게 읽기만 허용한다.
- 자동 키워드 제안은 `origin`과 `confirmed_at`으로 구분한다. 분석에는 `summary_source`, 신뢰 수준, 근거, 버전, 입력 해시를 기록한다.
- API 메타데이터에 30일 갱신 기한을 기록한다. 실제 갱신·삭제 처리(T-023) 완료 전 운영 수집은 시작하지 않는다. 자세한 근거와 검증 경계는 `doc/개발기반.md`를 따른다.

### 8.2 초기 인증 및 조회 결정 (2026-11-11)

- 사용자의 요청에 따라 Google OAuth로 로그인한다. 앱에서 이메일·비밀번호를 입력받거나 비밀번호 가입/메일 초대 절차를 제공하지 않는다. Supabase가 인증 사용자와 세션을 관리한다. 초기 이메일·비밀번호 로그인 방식은 T-030에서 대체한다.
- 로그인/로그아웃은 서버 액션, 세션 갱신은 Next.js Proxy에서 처리한다. 서버 조회 시 검증된 사용자 ID를 확인하고 사용자별 소유 데이터만 요청한다. 세션이 포함된 응답을 공유 캐시하지 않는다.
- Google 인증 후 `/auth/callback`에서 PKCE 코드를 세션으로 교환하고 세션 쿠키를 보존한다. 로그인 복귀 경로는 앱 내부로 제한하고, 고정 콜백 URL을 사용한다. Google/Supabase 공급자 및 리다이렉트 설정은 `doc/Google로그인설정.md`를 따른다. Google 첫 가입 허용 및 대상 계정 범위는 외부 인증 설정에서 관리한다.
- 초기 라이브러리는 최신 공개 영상에 대해 제목 검색, 자막 표시 필터, 50개 단위 페이지 이동을 지원한다. 갱신 기한이 지난 메타데이터는 숨기며 실제 갱신·삭제 경로는 T-023에서 구현한다.
- 사용자는 Vercel 첫 배포와 Supabase 초기 SQL 적용을 완료했다고 확인했다. 실제 원격 계정 로그인, 저장 후 재접속, 두 계정 접근 분리 검증은 T-024에 유지한다.

## 9. 기술 스택

- **프론트엔드/백엔드:** Next.js (App Router), TypeScript, Route Handlers/Server Actions
- **UI:** Tailwind CSS, shadcn/ui
- **배포:** GitHub → Vercel
- **저장:** Supabase PostgreSQL (Supabase Auth 및 RLS 적용 권장)
- **영상 메타데이터:** YouTube Data API v3

- **분석:** 로컬 규칙 기반 키워드 초안 → 자막 확보 시 선택적 AI 요약(Gemini 등, 별도 비용 및 무료 한도 검증)
- **비밀 정보:** Vercel 서버 환경변수로 관리; API 키·서비스 롤 키 클라이언트 노출 금지

## 11. 단계별 개발 계획

### Phase 1 — 수집·저장 (필수)
- 채널 등록 및 공개 영상 페이지 수집
- 영상 검색, 메타데이터 저장, 자막 표시 여부 구분
- 영상 라이브러리/필터, 중복 방지

### Phase 2 — 콘텐츠 사전
- 고정 카테고리 13개 + 디테일 키워드 + 서머리
- 상세 편집, 자막 붙여넣기, 분석 출처 표시
- 사용자가 선택한 영상만 분석

### Phase 3 — 마케팅 매칭
- 월별 요청 키워드 등록
- 후보 정렬·선정·제외·추천 근거
- 월별 CSV 내보내기

### Phase 4 — 고도화 (선택)
- 권한/약관 검토가 끝난 자막 확보 경로 연동
- AI 분석 품질/비용 개선, 시맨틱 검색, 사용자 피드백 반영

## 12. 주요 리스크와 결정 필요 사항

1. **수집 대상 범위:** 특정 브랜드 공개 채널 우선인지, 유튜브 전체 검색 우선인지 확정 필요(둘 다 지원 설계).
2. **자막 원문:** 브랜드 계정 권한이 없으므로, 제3자 영상의 자동 원문 확보를 당연한 기능으로 약속하지 않음.
3. **요약 품질:** 자막 없는 영상은 메타데이터 기반 초안일 뿐임을 표시.
4. **무료 요금제:** Vercel/Supabase/AI 서비스의 상업적 사용 가능 여부 및 최신 무료 한도는 실제 가입·운영 전 재확인.
5. **인증:** 혼자 쓰는 내부 도구인지 여러 담당자가 쓰는지 확정 후 사용자 권한 설계.
6. **데이터 저장 정책:** YouTube API 데이터의 캐시/보관/갱신 및 표시 관련 정책을 구현 전에 확인.

## 13. MVP 완료 조건

- [ ] 지정한 공개 유튜브 채널의 영상을 페이지 단위로 가져오고 재수집해도 중복되지 않는다.
- [ ] 수집한 영상을 Supabase에 저장하고 재접속 후 조회할 수 있다.
- [ ] 자막 표시 상태와 자막 원문 확보 상태를 구별해 보여준다.
- [ ] 영상에 대표 키워드 여러 개, 디테일 키워드 여러 개, 서머리를 저장하고 수정할 수 있다.
- [ ] 메타데이터 요약과 자막 기반 요약을 명시적으로 구분한다.
- [ ] 월별 키워드로 후보 영상을 찾고 최종 선정 목록을 CSV로 내보낼 수 있다.
- [ ] 주요 에러(쿼터 초과, 네트워크, 영상 비공개/삭제, 분석 실패)를 안내한다.
- [ ] 비밀키가 브라우저 번들·저장소에 포함되지 않는다.
- [ ] `AGENT.md` 지침에 따라 `history.md`, `todo.md`가 실제 작업마다 갱신된다.
